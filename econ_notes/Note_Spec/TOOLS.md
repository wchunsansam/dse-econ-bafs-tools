# 教具與小工具規劃

筆記負責「講得清、填得出、畫得上」。教具只在**動手比靜態圖更能建立機制**時才做。

## 1. 先問要不要做

做教具，若學生改一個量、立刻看到考試在問的那種變化（變／不變、分類對錯、哪邊成本較低）。

不做教具（用筆記的表、鏈、例子就夠），若：

- 只是背定義
- 只是看一張不會動的流程
- 只是把選擇題做成華麗按鈕
- 該機制已有全站獨立模擬器（不要複製一份進本章 lab）

一章的教具**不必平均覆蓋每一節**。先做該章考試反覆打的機制，其餘用筆記。寧可三個好用的，不要七個裝飾。

## 2. 一章一個 lab 頁

路徑慣例：`econ_tools/chXX_lab.html`。

一頁內多個工具，用分頁 + `location.hash` 切換（`#widget-id`）。筆記用 `data-tool="widget-id"` 跳進來。

Lab 頁自己有：返回首頁、開回該章筆記、繁／EN。語言用同一套 `.zh` / `.en` 與 `?lang=`。

不要：每個小工具一個新網域、一個 React 專案、或把 lab 嵌進筆記 iframe。

## 3. 筆記與 lab 的雙向連結

- 筆記 metadata：`lab` 指向該章 lab。
- 節內只在教完對應概念後放一顆 `.tool-link`。標籤寫人話（「教具：……」），不要寫檔名。
- Lab 每個工具要能單獨靠 hash 打開，切換工具時清掉舊的輸入／點擊處理，避免殘留 listener。
- 題材與人名跟 CONTENT.md 的課堂層；官方欄目的故事不要搬進 lab 當預設案例。

## 4. 設計教具時的方法

1. **寫一句「這個工具證明甚麼」**（最好是 DSE 會問的句子，例如某量改變後成本是否 necessarily 不變）。沒有這句就不要做。
2. **最小控件：** 滑桿、數字、可排序的兩三個選項、分類拖放或點選。不要儀表板。
3. **狀態要可見：** 選了／放棄了／其他，用與筆記相同的語意色（紫選中、橙放棄）。結果區清楚寫「變了」或「沒變」。
4. **預設值用課堂情境**，但學生改數字後結論仍要符合定義，不能只在預設值才對。
5. **雙語：** 介面標籤、按鈕、結果句全部成對。
6. **觸控：** 分頁與按鈕 min-height 約 44px；`input` 16px。窄屏單欄。
7. **不要在 lab 重做畫筆／填空／PDF。** 那是筆記與 pdf_mark 的工作。

## 5. 常見教具類型（按機制選，不按章名選）

| 類型 | 適合的機制 |
|---|---|
| 排序／鎖定基準再改價值 | 機會成本是否隨其他選項價值而變 |
| 兩項方案的加總比較 | 金錢 + 非金錢成本 |
| 分類器（點選或兩堆） | 成對概念：微觀／宏觀、物品類型、政策視角 |
| 滑桿 | 相對比較（數量 vs 慾望、利率高低） |
| 流程點選 | 因果鏈上「這一步動、下一步才動」 |
| 小計算器 | 公式短、數字會考 |

同一章裡類型可以重複，但每個工具仍要有自己那句「證明甚麼」。

## 6. 不要做的教具

- 重寫已上架、且被標為不要改的模擬器。
- 把整份筆記變成「互動課本」（每段一個小遊戲）。
- 需要後端、登入、或即時多人同步的課堂競賽（除非老師另開專案）。
- 為了動畫而動畫。

## 7. 書本練習 PDF

那不是 lab。掃描／官方練習 PDF 放 `econ_notes/tb/`，經筆記頂欄開 `pdf_mark.html?file=tb/….pdf`。檔名只准 `tb/` 下安全字元。學生在 PDF 上畫的筆跡存在該檔的 localStorage key，與筆記 `inkKey` 分開。

新章若有書本練習／答案，在該章 json／frontmatter 填四條路徑（中英 × 練習／答案）。沒有就留空，頂欄會隱藏。
